**`v1.1.0 → v1.2.0` is SUPPORTED** — strict expand-only forward migrations (no drops/rewrites on
applied state), per-module gap-versioned bands isolated by construction, and `spring.flyway.out-of-order=true`

release beyond `payments_rail.rail` (M5 S0, `ADD COLUMN … DEFAULT 'pix'`) and the additions of S1–S4.

## What ships (M5, by step)

- **S0 — PaymentRail seam (abstraction proof):** `PaymentRail` + `RailAssignmentPort` ports,
  `PixRail` strategy, V113 expand-only `rail` column. **PIX domain zero edits**; application 2 files
  disclosed; full suite + floors prove PIX byte-identical (`docs/audit-m5-s0.md`).
- **S1 — Card as the 2nd rail:** `method:"card"` + `cardToken` → PENDING (`brcode:null`) → PSP
  charge webhook → CONFIRMED on the same outbox/ledger path; PSP 402 → instant FAILED, zero
  journal, idempotency key deleted; reconciler confirms approved charges without a webhook.
  `CardPaymentIT` (approve/decline/replay/reconciler), `CardChargeAdapterTest`.
- **S2 — Redis read cache (fail-open):** one hot read path (idempotent-replay) with hit/miss/failopen
  metrics; Redis down = DB fallback, never fail-closed for reads (`ReplayCacheIT`).
- **S3 — k6 hard gate:** the money path is now a CI tripwire (create/replay/pay/confirm), seeded
  from the E16 honest baseline, **bite-proof by construction** (impossible-threshold leg MUST exit
  red). Runs on push-to-main + dispatch only.
- **S4 — Webhook reprocessing admin:** `POST /v1/webhooks/reprocess` re-drives a stored
  `webhook_events` row through the intake core (dedupe-safe); dedicated
  `DARGENT_WEBHOOK_REPROCESS_ADMIN_KEY`; real-actor audit keyed to the payment txid;
  `dargent.webhook.reprocess{outcome}` frozen metric.
- **S5 — Docs + flip + citation:** design/README/paybook/milestones flipped; scenario catalog card
  rows; release notes (this file); E17 citation on `docs/epics.md`.
