## What ships (capabilities by milestone, one line each with the delivering epic)

- **M0 — Skeleton (E0):** Java 25 multi-module Maven monolith (payments/ledger/notifications/shared,
  ArchUnit boundary gates), compose stack (Postgres 16, LocalStack SNS/SQS FIFO, NGINX),
  Flyway per-schema gap-versioned migrations, CI from day one. *(E0, 2026-08-28)*
- **M1 — Create path (E1–E4, remediated by E3R):** PIX dynamic BR Code creation via PSP simulator
  cob lifecycle; request-level idempotency keys (byte-equal replays, 425 in-flight);
  API-key auth (SHA-256 hashes, indexed prefix); canonical error contract; signed webhook intake
  (HMAC-SHA256 fail-closed, 5-minute anti-replay, provider-event dedupe, raw-payload persistence
  even on invalid signatures). *(2026-08-30)*
- **M2 — Events backbone & double-entry ledger (E6, E7, E10):** transactional outbox → SNS/SQS FIFO
  relay (at-least-once, DLQ, retention); append-only double-entry ledger with `ΣDR=ΣCR` journal
  invariant, balances projection, daily balance proof + rebuild, D+1 settlement; notifications
  consumer with `GET /v1/notifications`. *(2026-09-02)*
- **M3 — Suffering: refunds, expiration, delivery hardening (E5, E8, E9):** payment expiration +
  resurrection exactly-once; live reconciler confirming without webhooks (the signature guarantee);
  partial/total refunds with fee reversal and DB-arbitrated concurrent-refund + balance-drain
  guards; outbox backoff → FAILED → EXHAUSTED lifecycle with audited requeue and admin republish.
  *(2026-09-04)*
- **M4 — Production shape (E11, E12, E13):** observability (JSON logs with ECS correlation, txid
  drill, frozen metrics series, management port, prod lockdown proven by test); blue-green deploy
  by immutable tag with 10/30/100 canary, instant rollback, runtime-smoke + shutdown-under-load in
  CI; full quality/security gates (SpotBugs, Spotless, JaCoCo floors on combined unit+IT data,
  OWASP NVD-keyed, Trivy 2-pass + SBOM, CodeQL security-extended, Dependency Review, evidence-lint).
  *(2026-09-07)*
- **v1.0.0 release engineering (E14):** GHCR `sha-<short7>`+`edge` per main commit; annotated-tag
  release workflow (gates re-run on the tagged commit, semver image push, CycloneDX SBOM of the
  exact pushed digest, Release carries the jar extracted from the shipped image); backup/restore
  machinery with manifest-verified restores and the CI restore drill (destroy + restore + verify,
  RTO measured); outbox republish tooling. *(2026-09-07)*

## Architecture snapshot

Modular monolith, schema-per-module (no cross-schema FK/JOIN), events-only cross-module
communication (outbox → SNS → SQS), the database arbitrates every race (conditional UPDATEs,
SELECT … FOR UPDATE on refund creation), Money as `cents:long` end-to-end. Deploy topology:
NGINX :8080 → api-blue :8081 / api-green :8082 over one shared database; LocalStack (SNS/SQS
FIFO) disposable by design. Full design: `docs/design.md`.

## Two-release migration verdict (runbook §2 item 3)

> **Two-release migration review (v0.3.0 ↔ v1.0.0): 10 of 11 migrations are expand-only
> (TD-33 ALLOW-with-log for the three relaxations). One contract violation: V301 content changed
> post-v0.3.0 without a version bump — v1.0.0 code fails Flyway validation against a genuine
> v0.3.0 database. No v0.3.0 production deployment exists, so the impact is the upgrade path,
> not any live system. Remedy (a) recommended: V301 reverted to v0.3.0 content + V302
> notification table (forward-only). Pending owner decision.**

Full audit with the empirical reproduction: `docs/releases/v1.0.0-migration-review.md`.

## Known accepted risks

- **DEBT-7** (post-v1.0.0): `postJournal`/`postJournalWithoutBalances` duplication in the ledger
  store adapters — deliberate (owner adjudication 2026-09-06) to keep E8/E9 guarantees untouched.
- **DEBT-8** (accepted for v1): no rate limit / request body cap on the public webhook route —
  PSP-only topology in v1; NGINX edge rate-limiting + body cap when a public deployment exists.
- **Tracing**: trigger-activated (not always-on) — documented in observability docs.
- **PITR/WAL**: archival config shipped (`deploy/systemd/postgres-wal-archival.conf`, 15-min
  policy) but the PITR restore path is **shipped-not-drilled** — declared in the drill record.
- **V301 history defect** (this release, finding F1): upgrade path from v0.3.0 databases is
  blocked pending the owner's remedy decision — see the migration review.
