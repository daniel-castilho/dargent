## Procedure (verbatim behavior)

D1 boot seeded stack → D2 backup (dump + manifest) → D3 **destroy the cluster** (`down -v`) →
D4 restore into the fresh cluster (`pg_restore` → Flyway no-op check → per-table counts vs
manifest → balance proof ΣDR=ΣCR + projection==lines) → D5 post-restore money path through the
front (new txn CONFIRMED) → D6 teardown.

## Negative paths proven (2026-09-07)

- **Tampered manifest count** (`payments.payments` 13→14): restore verified counts, caught the
  mismatch, `exit 1`:
  `MISMATCH: payments.payments expected=14 actual=13` →
  `RESTORE ABORT: 1 table count mismatch(es) against the manifest — restore UNVERIFIED`
- **Outbox republish tool** (Q2 conditions, all four paths):
  - key unset → `exit 1`, actionable message (fail-closed precondition ii)
  - relay OFF → WARN + proceed; the call reports the 404-with-reason (controller 404-hidden
    without `DARGENT_RELAY_ENABLED=true` — documented nuance, condition iii)
  - happy path → `matched=4 republished=4 window_rows=4 (fully covered)` `exit 0`
  - >500-row window → `matched=500 republished=500 window_rows=501` → **FAIL** with the
    split-window instruction, `exit 1` (condition i — the endpoint caps at 500/call and does
    not consume the window; the tool refuses to look successful while rows remain)

## Shipped-not-drilled (honest declaration, per the S3 contract)

- **WAL archival / PITR** (`deploy/systemd/postgres-wal-archival.conf`): host-side config,
  shipped as files, NOT CI-drilled — the RPO ≤ 15 min claim rests on the 15-minute WAL policy,
  whose restore path (PITR) is declared untested in v1.0.0. Post-v1.0.0 candidate: a live PITR
  drill (optional, owner queue).
- **Systemd units** (`deploy/systemd/dargent-backup.{service,timer}`): shipped as files; the
  nightly cadence itself is host-side and not CI-testable. The drill proves the scripts the
  units invoke.
- The CI `restore-drill` job (workflow_dispatch) executes this same drill in CI; its run id +
  artifacts are the citable evidence for the release chain (release.yml gates include it).
